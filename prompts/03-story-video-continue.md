## 1. 오늘 할 일 (순서대로)

### 1-1. 화질 개선 시험 — 가장 먼저
문제: 동작 클립을 640×352로 만들어 1080p로 3배 늘려서 흐리다(정지 그림보다 확연히 뭉개짐). 영상 대부분이 클립이라 화질을 이게 결정한다.
- 시험할 3가지 (ep5c 클립 2~3개, 같은 첫 프레임·같은 프롬프트):
  1. LTX-2.5를 960×544로 직접 생성
  2. LTX 공식 공간 업스케일러로 2배 (내장 `LTXVLatentUpsampler` 노드 + 업스케일러 모델)
  3. 프레임 업스케일러 (safetensors판만)
- 2·3번에 필요한 모델은 **이름·용량·라이선스·저장 경로 표를 보여주고 내 승인 후** 다운로드.
- 기록: 클립당 시간, 최대 VRAM, 모델 적재 시간, 깜빡임 여부.
- 비교: 같은 프레임을 100% 크기로 잘라 나란히 붙인 이미지 + 한 편(클립 약 55개) 예상 시간 표.
- 저비용 개선도 같이: `story_video.py`에서 클립을 원래 해상도로 읽고 고품질(lanczos) 확대, 출력 비트레이트 8 Mbps 이상, 1440p 출력 옵션.
- 결과를 보여주고 **어떤 방식으로 갈지 내가 고른 뒤** 코드에 반영.

### 1-2. 고른 방식을 ep5c에 적용
- 클립 전체 재생성 또는 업스케일 → 재렌더 → 이전 버전과 같은 장면 비교 이미지.
- 정지 화면 비율(1초 이상 변화 없는 구간)과 자막 검사(두 문장 붙은 자막 0개)를 다시 측정.

### 1-3. BGM을 분위기별로 나눠 쓰기
- 블라인드 결과: 긴장·엔딩은 Stable Audio 3.0, 따뜻한 장면은 ACE-Step 1.5 XL SFT.
- story.json `"bgm"`을 `{"engine": "sa3"|"ace_sft", "prompt": ..., "scenes": [...]}` 목록으로 받게 하고, 파이프라인 bgm 단계에서 엔진별 워크플로 선택 + 끝 무음 꼬리 자르기 + 클리핑 방지 리미터.

### 1-4. ep5c 남은 그림
- 13장과 15장이 같은 그림 → 15장(칠복의 고백, 스무 해 전 이야기)을 대사에 맞게 새로 그린다. 핵심 장면이면 GPT, 아니면 로컬.

## 2. 지킬 원칙 (어제 정한 것)
- **결함이 없고 상황에 맞는 장면이 동작보다 우선.** 그림을 대사와 먼저 대조, 동작은 잔잔하게(시선·표정·불빛·천천히 확대), 손·소품을 다루는 위험한 동작은 피함. 클립마다 6프레임 띠로 검수하고 결함은 동작을 줄여 다시 만듦.
- **표정을 바꾸라는 지시(eyes widen, smile fades, shocked 등) 금지**, 얼굴 클립은 얼굴만 잘라 24프레임 띠로 검수. 원인·방지법: `docs/STORY_WORKFLOW.md`.
- GPT는 이미지 생성만(썸네일·도입·다인물 핵심 장면). 스토리 구성·청취자 검수는 Claude. 승인한 GPT 원본은 `story_gptimg.py approve`로 LoRA 데이터에 자동 수집.
- 모델 파일은 **safetensors만**, 피클(.pth/.pt/.ckpt) 금지. 다운로드·커스텀 노드 설치·ComfyUI 업데이트는 **내 승인 후**. ComfyUI는 127.0.0.1에서만.
